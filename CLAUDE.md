# Taste Profile — Multimodal Shareable Taste Context System

## Project Overview

A web app that lets users build a rich, structured taste profile from multiple modalities (images, music, text preferences), share it with others, and query Claude with one or multiple profiles as context. Built on the Anthropic API for the Creative Flourishing hackathon track.

The core insight: Claude can extract structured aesthetic and cultural signals from images and music references, accumulate them into a coherent "taste fingerprint," and then use that fingerprint to power personalized recommendations, cross-domain suggestions, and multi-person compatibility queries.

## Architecture

```
User Input (images, music refs, text preferences)
    │
    ├──► Image Analysis ──► Structured visual aesthetics (JSON)
    │    (Claude vision API)
    │
    ├──► Music Analysis ──► Structured sonic/cultural profile (JSON)
    │    (Claude text API, from artist/track/genre names)
    │
    ├──► Text Preferences ──► Structured preference data (JSON)
    │    (direct input: food, fashion, books, etc.)
    │
    └──► Profile Synthesis ──► Unified taste fingerprint
         (Claude API: reads all signals, outputs coherent summary)
              │
              ├──► Storage (persist per user, share across users)
              │
              └──► Query Interface
                   ├── Single profile queries
                   ├── Multi-profile blend (union, intersection, weighted, contrast)
                   └── Cross-domain recommendations
```

## Tech Stack

- **Frontend:** React (single-file .jsx artifact or standalone app)
- **API:** Anthropic Messages API (claude-sonnet-4-20250514)
- **Storage:** localStorage for solo dev/testing, or persistent artifact storage if deploying as an artifact
- **No backend required** — all API calls happen client-side or through a thin proxy

## Core Prompts

### Image Analysis Prompt

```
Analyze this image as a data point in someone's taste profile. Extract the following as JSON:

{
  "palette": [3-5 hex colors that dominate the image],
  "mood": "2-4 word mood description",
  "composition": "brief description of framing, balance, perspective",
  "lighting": "quality, direction, warmth of light",
  "texture": "surface quality, grain, smoothness",
  "influences": ["artistic or cultural references this evokes, if any"],
  "subject_matter": "what the image depicts",
  "tags": ["5-8 descriptive tags"],
  "aesthetic_signal": "One sentence: what does choosing this image reveal about someone's taste?"
}

Be specific and observational. Do not be generic. Ground every field in what you actually see.
```

### Music Analysis Prompt

```
A user has listed the following as music they love:

{music_entries}

For each entry, analyze:
{
  "artist": "",
  "track": "" (if provided),
  "genre": "specific subgenre, not just 'rock'",
  "sonic_qualities": "instrumentation, production style, vocal character",
  "mood": "emotional quality",
  "energy": 0.0-1.0,
  "complexity": 0.0-1.0,
  "era_influence": "what period or movement it connects to",
  "cultural_context": "what scene or community this music belongs to"
}

Then synthesize across all entries:
{
  "synthesis": "2-3 sentences on what this collection reveals about the listener's taste. Identify the through-lines, the contradictions, and what they might love that they haven't listed."
}
```

### Profile Synthesis Prompt

```
Here is a user's accumulated taste data across multiple modalities:

VISUAL:
{visual_analyses}

MUSIC:
{music_analyses}

TEXT PREFERENCES:
{text_preferences}

Synthesize this into a unified taste fingerprint. Write 3-5 sentences that capture:
- The core aesthetic thread connecting their preferences across modalities
- Any interesting tensions or contradictions
- The emotional register they're drawn to
- What kind of person this profile suggests (without being reductive)

Then provide:
{
  "fingerprint": "the 3-5 sentence synthesis",
  "keywords": ["10-15 words that capture this taste"],
  "cross_domain_predictions": {
    "travel": "where they'd love to visit",
    "restaurant": "what kind of dining experience they'd seek",
    "gift": "what kind of object they'd treasure",
    "architecture": "what spaces they'd feel at home in"
  }
}
```

### Single Profile Query Prompt

```
You have deep knowledge of the following person's taste:

{fingerprint}

Full taste data:
{full_profile_json}

The user asks: {query}

Answer drawing on everything you know about this person's preferences. Be specific — recommend actual things (real restaurants, real albums, real films, real places). Don't hedge. If their profile suggests they'd love something, say so with confidence.
```

### Multi-Profile Query Prompt

```
You have taste profiles for multiple people:

{profiles_with_labels}

Blend strategy: {strategy}

Strategies:
- "intersection": Find things ALL of them would enjoy. Look for overlapping aesthetics, shared moods, compatible preferences.
- "union": Find things ANY of them would enjoy. Cast a wide net across all their preferences.
- "weighted": Weight each person's preferences by the provided percentages. {weights}
- "contrast": Highlight where these people's tastes diverge. What would person A love that person B would hate, and vice versa?

Query: {query}

Be specific. Recommend real things. Explain why each recommendation fits the blend strategy.
```

## Key Design Decisions

- **All analysis happens through Claude** — no separate ML models to set up
- **Images are sent as base64 to the vision API** — no image hosting needed
- **Music analysis is text-based** — Claude's knowledge of music is deep enough that artist/track names give rich signals without audio input
- **Profiles are JSON blobs** — easy to store, share, merge, and inject into prompts
- **Synthesis is a separate step** — user accumulates data points, then explicitly triggers fingerprint generation, so they can see and edit the raw data first

## API Usage Notes

- Use `claude-sonnet-4-20250514` for all calls (fast, good at structured output, vision-capable)
- Set `max_tokens: 1024` for individual analyses, `max_tokens: 2048` for synthesis and queries
- Image analysis: send the image as a base64 `image` content block alongside the text prompt
- For structured JSON output: include "Respond only in JSON, no preamble or markdown" in the prompt
- Parse responses with try/catch — strip markdown fences if present before JSON.parse
